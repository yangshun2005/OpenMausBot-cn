# 一个机器人、文件夹、独立线程

现有的直接机器人 **Tasks** 变为 **Threads**。它们仍是相同的持久化记录和对话记录 ID，不是第二套对话系统。

## 产品模型

- **Bot（机器人）：** 共享的身份、指令、记忆、知识、已批准的技能、集成和计算机偏好。
- **Folder（文件夹）：** 一个机器人下的可选组织方式。例如：Email、Research、Website。它不是文件系统目录、模型设置、安全边界，也不是机器人的独立副本。现有的内部项目记录和 ID 保持不变；不再保留基于项目的模型继承。
- **Thread（线程）：** 一个持久对话，拥有自己的模型/账户、effort、审批偏好、运行状态、未读状态和停止控制。
- **Group（群组）：** 现有的多机器人频道/房间，保留其成员列表和独立的线程历史。机器人之间的交流仍可识别。

文件夹可以重命名。线程可以移动或保持未分组。删除文件夹会将其线程取消分组；不会删除对话或更改模型。选择不同的线程绝不会重定向已在运行的工作。新线程从机器人默认值开始，之后保留自己的选择。现有分区保留 Chief 分配和同伴可见性规则；它们绝不能迁移到装饰性文件夹中。

侧边栏在机器人下方显示最近/活跃的线程。**All threads（所有线程）** 是紧凑的可搜索选择器，在较小屏幕上尤其有用。模型选择器保留在聊天标题栏中，而 Ask/Auto 保留在输入框内；两者都作用于当前可见的线程。同一个机器人的对话不再有第二个 "Tasks" 区域。

侧边栏借鉴 T3 的紧凑可搜索对话层级：安静的机器人/群组标题、缩进的线程行、克制的活跃样式，以及工作/等待/未读指示器。无需仪表盘或项目创建步骤。Threads 是桌面端和移动端面向用户的导航术语。原生客户端独立固定所查看的线程，不受另一台设备选择的影响；原生文件夹导航是后续工作，不应被默认为已实现。

## 执行与资源归属

每个机器人默认同时运行三个直接线程。设置 → 通用 → 并行线程可将每个机器人的上限设为一到十。多余的消息在输入框上方等待，不进入对话记录，直到该机器人有空闲槽位；它们可以被取消。现有队列在每个等待线程内批量处理后续消息，并按顺序清空等待线程。它是内存中的，重启后不持久。提高上限会释放排队的工作；降低上限绝不会停止活跃轮次。等待人工审批的线程会占用一个槽位。原生提供商会话本就以线程为键；现在 harness 将调度、权限响应、中断、队列、未读状态和后台事件都保持在同一身份上。

普通线程设置提供 Ask 和 Auto。Full/Custom 提权仍沿用现有的受信任机器人设置流程；HTTP 任务补丁无法授予它。Webhook/无人值守状态是线程级的，因此在另一个线程中输入不会授予自动化运行有人值守权限。

新的本地代理线程获得独立的默认工作目录。现有的固定目录和提供商会话被保留。一个机器人的多个线程在一个选定的项目文件夹中并行工作，就像同一个仓库中的多个代理会话（每轮快照按文件夹自行排队；文件夹绝不是整轮的占用）。托管浏览器和主机计算机工具在首次使用时获取资源，并在该轮中保留它。竞争的线程会收到明确的拒绝，而不是交错执行屏幕操作。显式的 Local VM/VPS 工作和云生命周期操作保持保守。文件/文件夹协调**不是**针对 Full 访问提供商发出的任意命令的沙箱。

共享内存写入使用作用域化的 `memory_update` 工具：读取当前内存，追加或替换/删除一个确切条目，然后原子化持久化。过期或有歧义的替换会失败，而不是抹掉另一个线程的笔记。运行中的提示保留其初始内存快照；后续轮次会看到新笔记。现有的用户文件访问仍然受支持，不会被静默撤销。

当对话元数据被删除时，生成的线程文件会被保留；删除对话记录绝不能静默抹掉项目文件。此变更不包含自动文件清理、账户池化或外部 Codex/ChatGPT 同步。

## 有意为之的后续工作

- 可选的非活跃归档：从不 / 24 小时 / 1 周 / 1 个月。仅隐藏空闲、已完成的对话；保留历史，绝不归档正在运行的工作或待处理的人工审批。
- 独立的多机器人群组成员执行：保留现有的串行房间行为，直到该编排拥有自己的符合性测试。直接线程不得暗示对同一物理 VM 的并行控制。
- 原生移动端组织应使用相同的记录和固定控件，而不是另造一套移动端线程模型。
