状态：已实现（2026 年 10 月，`feat/local-environments`）。完整设计：
[2026-10-07 本地环境设计](../superpowers/specs/2026-10-07-local-environments-design.md)。
手动检查：[验证方法](../verification/local-environments.md)。

## 问题

一次桌面安装同时只运行一套配置：`~/.openmausbot` 下的机器人、提供商、群组、例程和历史记录。同时处理多个互不相关项目的人——比如一个业余无线电机器人团队和一个移动应用机器人团队——希望拥有完全独立的团队、模型选择和历史记录，并能在开始工作时选择正确的那一套。

## 形态

**具名本地环境**：同一安装可以重启切换到的额外数据目录，与已保存的服务器并列管理，同一时间只有一个处于活动状态。创建环境会注册一个名称和一个数据文件夹（"我的环境" → `~/.openmausbot-my-environment`，或通过原生选择器选定的文件夹）；切换会停止应用的服务器子进程，将其迁移到目标目录，进行健康探测，然后重新加载窗口——大约十五秒，切换失败则完全保持原状。当前数据文件夹仍为"这台电脑"，行为与之前完全一致：零迁移，且永远不会被遗忘。服务器本身不变——`OMB_DATA_DIR` 已经隔离了一切，每个目录的 `environment-id` 已经能区分两个环境。

环境所持有的一切都随之隔离：机器人、提供商实例和 API 密钥、MCP 服务器、群组、例程、消息历史、记忆和检查点。

## 所在位置

| 部分 | 文件 |
|---|---|
| 注册表：带版本的条目、v1→v2 迁移、名称/路径守卫规则 | `electron/environments.cjs` |
| 切换编排：停止子进程、移交数据目录租约、探测、仅在成功时持久化 | `electron/environment-switch.mjs`（纯函数，依赖注入） |
| 接线：IPC 接口、单切换互斥锁、监督进程暂停、回滚重启、启动回退到这台电脑 | `electron/main.mjs` |
| "这台电脑上的环境"——创建表单、切换、遗忘（可选择保留或删除文件） | `src/components/ConnectedWorkspacesSettings.tsx`（设置 → 服务器） |

维持模型成立的规则：

- 目录要么是绝对路径，要么无效；不能是默认目录，也不能位于已注册环境的目录内。
- `activeId` 仅在目标服务器通过健康探测后才写入，因此切换中途崩溃会启动上一个环境；启动时始终无法启动的环境会回退到这台电脑一次并告知用户。
- 数据目录租约随切换一起移动，因此两个应用进程永远不能共享一个环境；租约被持有意味着"正在别处运行"，切换会中止。
- 创建和切换是打包安装版的功能：未打包的开发运行返回 `dev`，且卡片不渲染。

## 非目标

与规范相同：同时运行两个环境、在活动服务器内热切换、复制或克隆现有环境（复制安装功能已覆盖迁移设置）、按环境的云同步或伴侣配对，以及多租户。
