# 计划：远程工作区

OpenMausBot 服务器可运行在任何地方；从桌面应用、任意浏览器或手机连接——使用真正的身份验证，而非回环信任模型。

## 为什么

一周内出现三个独立的需求信号：社区成员已在 VPS 上自托管，并询问如何从 Mac 连接；用户想要"从任意 PC 或手机打开聊天窗口"，因为 Linux 服务器比他们的笔记本更快；以及产品一贯承诺的：合上笔记本后例程仍能继续运行。工作负载的收益是实实在在的：服务器硬件更快、始终在线，且所有引擎 CLI 都能无头运行。

## 现状

- `docs/self-hosting.md`：Docker 租户栈（`deploy/`）将 Caddy 放入服务器的网络命名空间，并使用 basic-auth 登录；服务器仍绑定回环，其 Host/Origin 门禁由两条 header 规则满足。这是**当前**的托管路径，且仍然有效：远程工作区用每设备会话替换共享密码，而非替换整个栈。
- iOS 伴侣应用已通过二维码配对：短期配对令牌、持久化的每设备 bearer（静态存储时哈希）、Tailscale 感知的广播。远程工作区正是将此推广到所有客户端。
- 服务器自带 Web UI，因此"任意 PC"无需新应用。

## 一段话设计

应用引入**环境**概念：一个保存的工作区列表（Local 为默认），每个工作区有稳定的服务器身份、名称、URL 和会话。添加环境使用**一次性配对**：服务器生成短期代码，以二维码或配对 URL 展示；客户端一次性兑换为持久的每设备会话。远程性只存在于连接层——一个运行时边界、相同的 API 和事件流，绝不为"远程"另设一套功能。

## 设计要点（来自参考的桌面加服务器设计）

我们研究了一个已发布的设计，它为桌面优先的 agent 应用解决了同样的问题，并将以下要点采纳为需求：

1. **稳定的服务器身份。** 服务器一次性生成 `environmentId`（`OMB_DATA_DIR/environment-id`），并在 `/.well-known/openmausbot/environment` 提供描述符——id、label、platform、version、capabilities。客户端在每次连接时验证 id，不匹配则大声拒绝（URL 被复用但指向了不同的服务器）。
2. **两阶段凭证。** 配对码：12 个字符，取自 32 符号的无歧义字母表（60 位），拒绝采样，**5 分钟** TTL，单次使用。在 `POST /api/auth/pair` 一次性兑换为不透明会话令牌：随机字节，**静态存储时 sha256**（伴侣应用的纪律），30 天过期，使用时续期，自配对起最长 180 天，记录每设备标签，可从设置中撤销。配对 URL 将代码放在 **hash** 中，绝不放 query。
3. **绝不将会话令牌放入 URL。** 事件流是 SSE，`EventSource` 无法设置 header，因此通过已认证的 `POST /api/auth/stream-ticket` 生成带用途标记的 5 分钟票据，只有该票据出现在 `/api/events?ticket=` 上。未来任何 WebSocket 同理。
4. **浏览器客户端使用 cookie，而非 local storage。** `httpOnly`、`SameSite=Lax`，请求经 HTTPS 到达时加 `Secure`，按**端口加实例哈希**命名。命名只是防止同一主机上的两个服务器互相覆盖 cookie；浏览器仍会向主机上的每个端口发送 cookie，因此实例间的隔离来自不同的主机名，而非命名。LAN 上的明文 HTTP 会明文传输 cookie，文档中注明仅限私有网络。
5. **作用域从第一天起就有，且小。** `client`（聊天、房间、例程、审批）和 `admin`（配对、撤销、引擎和 MCP 配置、设置）。Admin 路由在门禁旁的一张表中列出；其余需要 `client`。v1 中回环保留其隐式 `admin`，因此桌面应用不变，这使得一条规则至关重要：**代理绝不能将 `Host` 重写为回环**，否则每个远程请求都变成所有者。Docker 栈转发真实的 `Host` 并依赖会话（其共享密码变为可选）；自托管文档对其他代理也如此说明。后续的配置标志将为托管租户要求所有连接都使用会话。
6. **端点是提示，且分级。** 服务器广播回环、LAN、私有网络（Tailscale）和 HTTPS 端点；用户的默认值按**类型**记忆，因此 LAN IP 变化不会破坏它；配对二维码中不会静默回退到回环。仅回环的服务器会明确说明，而非打印不可达的 URL。
7. **一个监督者负责重连。** 固定阶梯 3 秒、4 秒、8 秒、16 秒，稳定 30 秒后重置，离线不消耗尝试次数，并严格区分*瞬态*失败（重试）和*受阻*失败（凭证错误、已撤销、版本不支持：等待用户）。
8. **版本偏差是一条带单一操作的横幅**，以服务器广播的 `selfUpdate` 能力为键：Docker/systemd 显示"更新服务器"，桌面应用运行服务器时显示"更新应用"。旧服务器通过能力缺失处理，绝不解析版本号。
9. **磁盘上的机密**：目录 `0700`，文件 `0600`，用 `wx` 一次性创建，原子临时文件加重命名。签名机密和会话哈希存放在此；任何机密都不记录日志，包括隧道 CLI 的 stderr，其在到达日志前被归类到封闭的标签集。
10. **启动不等于访问。** 服务器如何存在（Docker、systemd、某人的笔记本）与客户端如何与之通信（直接 URL、私有网络、托管隧道）是分开的。启动来源仅是 UX。
11. **参考设计缺少的暴力破解防护。** 每分钟每个来源五次失败的兑换，锁定该来源的配对十分钟；所有来源共三十次则锁定所有人一分钟；每次失败都记录来源。仅当连接来自同一机器上的代理时，来源才是 `X-Forwarded-For` 的第一跳（服务器绑定回环，Caddy 会覆盖客户端发送的任何转发 header）；否则来源是 socket 对端。同一来源在一分钟内再次提交已消费的代码会得到相同答案，因此丢失的响应不会让设备陷入困境。

## 传输方式

1. **显式 URL**，面向自托管者：Docker 栈的 HTTPS 域名、SSH 隧道或私有网络。最先发布。
2. **私有网络助手**：检测 Tailscale MagicDNS 名称，并为 HTTPS 提供 `tailscale serve`，使用服务器的实际端口（TLS 由 Tailscale 提供；服务器从不终止 TLS）。已作为命令行 `openmausbot serve --tailscale` 发布。
3. **托管隧道**：伴侣应用已使用的 cloudflared 托管隧道通道——零网络配置。复用相同的会话。已作为命令行 `openmausbot login` + `serve --tunnel`（`server/tunnel.ts`）发布：隧道网关转发到 harness 上的第二个 IPC 监听器，按构造，其上的每个请求都"经过代理"。

基础 URL 在运行时按连接解析。渲染器 bundle 中不烘焙任何 origin；提供的 UI 继续使用相对路径。

## 与企业轨道的关系

会话层是企业身份轨道扩展的接缝：当 `users` 到来时，会话获得 `userId`，前置的 OIDC 代理（Authentik、oauth2-proxy）可从身份 header 而非配对码生成会话。这些 header 仅从配置的代理（回环对端，客户端发送的副本被剥离）信任，绝不从直接客户端信任，且该边界有自己的测试。这一步不会丢弃这里的任何东西。

## 非目标（v1）

- 桌面管理的远程服务器 SSH 启动（Docker 路径已覆盖，且无需承担 shell 环境的支持负担）。
- 超出 Tailscale 提示的自动检测端点选择器。
- 无 HTTPS 的公网暴露，以及在会话落地前，Docker 栈的登录墙。

## 排序

1. `docs/self-hosting.md` + Docker 栈——已发布。
2. 服务器：环境 id + 描述符、配对 + 会话 + 流票据 + 作用域表 + 锁定（约 1 周，全部在测试下）。
3. 客户端：环境列表、配对屏幕（粘贴 URL 或扫描）、会话监督者、版本横幅；提供的 Web UI 获得 cookie 路径（约 1 周）。
4. 桌面端的 Tailscale 助手和托管隧道（各约 3 天）。
5. 企业身份扩展该接缝（独立轨道）。
