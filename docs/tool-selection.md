# 工具选择

打开机器人的 **访问 → 工具选择** 设置，可减少发送给其模型的工具。这对上下文窗口较小的本地模型很有用。

- **所有当前工具** 保留现有引擎和集成默认值。
- **自定义选择**，勾选 **仅允许列出的工具** 时，只提供允许列表中的工具。允许列表为空则**不选择任何工具**。
- 取消勾选 **仅允许列出的工具**，则保留当前目录，但排除列表中的工具除外。排除始终优先。

每行输入一个选择器，然后选择 **保存工具选择**。更改在下一轮生效。保存前请先完成机器人正在执行的任务。保存失败绝不会授予新启用的工具。移除工具访问权限的更改即使保存失败，也可能在运行中的应用里继续生效；重试保存以在重启后保留这些更改。复制机器人会保留创建副本那一刻的选择。

## 名称与示例

使用工具的原始名称（区分大小写），不要用任何模型特定的别名：

```text
native:read
mcp:mail:read_notes
```

`native:*` 包含引擎的原生工具。`mcp:mail:*` 包含名为 `mail` 的已配置服务器上的所有工具。部分通配符（如 `native:read*`）无效。有效但不可用的名称不会选择任何工具，也不会回退到所有工具。允许和排除列表各最多接受 256 个选择器，每个选择器最多 1024 个字符。

**Pi 起草**，勾选仅允许列出的工具：

```text
native:read
native:edit
native:write
```

**Grok CLI 起草**：

```text
native:read_file
native:search_replace
native:write
```

**Pi 搭配一个自定义 MCP 工具**：

```text
mcp:mail:read_notes
```

同时要在现有的 MCP 服务器卡片中选择 `mail` 服务器。选择器不会启用已禁用的服务器、连接账户或授予集成访问权限。

**Grok CLI 搭配一个自定义 MCP 工具** 需要显式选择其原生查找和调用工具：

```text
native:search_tool
native:use_tool
mcp:mail:read_notes
```

Grok 用这两个辅助工具来发现和调用所选的 MCP 工具。它们的结果和调用会按相同的原始选择器进行检查。Pi 则直接将所选的 MCP Schema 发送给模型。

## 引擎支持

| 引擎 | 可用选择 |
| --- | --- |
| Pi、Grok CLI、Grok API、OpenAI 兼容、Mistral、MiniMax | 原生工具和应用提供的 MCP 工具 |
| Claude、Codex、Gemini、Kimi、Droid、Cursor、OpenCode Go、Qwen、Hermes、Custom ACP、Antigravity | 应用提供的 MCP 工具；在允许列表中保留 `native:*`，且不要排除原生工具 |
| Boat native | 不支持有意义的工具限制 |

Grok CLI 的原生契约已在版本 **1.0.41** 上验证。其他版本在契约验证前会拒绝原生限制。继承的 Grok 配置文件限制仍然适用。Grok 接受简单的 `[agent]` 名称/定义条目（包括行尾注释），以及显式的 `--agent-profile` 文件。带引号或带点的键、内联 agent 表、多行 TOML、冲突的配置文件来源和 CLI 工具覆盖，在无法安全解析其现有约束时会拒绝受限轮次。受限 Grok 会禁用其托管的 MCP 网关；出现意外的原生 MCP 服务器会阻止提示启动。受限 Claude 需要具备严格 MCP 隔离的现代 CLI，且无法继承其原生 MCP 配置。受限 Codex 在启动提示前会检查其生效的 MCP 配置。每个 Codex MCP 挂载在新线程和恢复线程上都保留独立的私有网关设置；自定义服务器保留审批提示。

不支持的限制和格式错误的已保存选择会以设置错误终止轮次。设置警告是刻意为之：它不会声称引擎能强制执行其契约不支持的约束。其他 CLI 引擎的原生选择仍是后续贡献，需要经过验证的提供商契约。

## 审批与访问

选择会缩小可用工具的范围。现有的审批模式、访客限制、集成权限和主机控制确认仍然适用。自动或完全审批不会重新启用被排除的工具。MCP 发现和调用都会被过滤，包括基于 URL 的服务器和零结果预算。

这是工具可用性，不是命令、文件访问或凭据的沙箱。允许某个 shell 工具仍然允许该工具现有的权限。机器人提议的配置文件更改无法编辑此所有者设置。
