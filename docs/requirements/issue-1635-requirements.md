# Issue #1635 — 按更新顺序排列的线程，以及置顶

## 目的

线程列表按线程最后更新的时间排序显示。置顶的线程保留在该顺序之上。

当前列表会把需要注意的线程（waiting / working / queued / unread / 打开的线程）浮到上方，其余按保存数组的顺序排列。保存数组只在创建时加到头部，继续对话也不会移动。机器人可以置顶，但线程不行。

## 范围

- 桌面端侧边栏、折叠时的其他线程、All-threads 选择器
- iOS 的线程树和管理面板
- Android 的线程树和线程面板
- 机器人的线程，以及用户创建频道的线程
- 置顶的保存，以及从三个客户端进行置顶/取消置顶

## 非范围

- 线程的拖拽排序
- 消息置顶（`pinnedMessageId`。维持现状）
- 机器人本身的置顶、文件夹的保存顺序、Attention inbox 的排序
- 改变工作目录置顶（`cwd` / `pinnedCwd`）的含义

## 术语

- **更新时间**：该线程最新消息的 `at`。没有消息时使用创建时间 `createdAt`。
- **置顶**：人为添加的标记。带置顶的线程显示在未置顶线程之上。置顶之间也按更新时间从新到旧排列。

## 验收条件

1. 有消息的线程，最新消息越新越靠上。没有消息的线程使用创建时间。同一时刻保持此前的数组顺序。
2. `pinned: true` 的线程显示在未置顶线程之上。置顶之间按更新时间从新到旧排列。
3. waiting / working / unread / queued 仍作为徽标或状态显示保留。它们不改变排序。
4. 桌面端默认列表显示打开的线程中更新最新的 6 条。置顶、需要注意的线程和当前打开的线程不计入这 6 条，且在这 6 条之外仍然保留。已关闭和已归档的线程，仅在置顶或需要注意时保留。
5. 「全部显示」和搜索在展开折叠后，按相同的置顶＋更新顺序排列。搜索的匹配条件不变。
6. 置顶可从线程操作菜单中置顶/取消置顶。工作中也可置顶/取消置顶。不兼作归档或删除。重启后仍然保留。
7. 置顶的线程，无论已关闭还是已归档，都保留在默认列表中。
8. 频道的线程也具有相同的顺序和置顶。bot-to-bot 的 DM 仍和以往一样保持 1 个线程。
9. `updatedAt` 由服务器决定。不能通过客户端的 PATCH 写入。除 `pinned` 以外的线程设置授权不变。
10. 不认识该字段的旧版 companion 会忽略未知键，按以往方式运行。
11. 桌面端、iOS、Android 的线程行按 OS 的时区和区域设置显示更新日期时间。日期和时刻都显示。不固定为 UTC。没有时刻的行保持为空。

## 约束

- 桌面端、iOS、Android 的顺序规则保持一致。文件夹的排列维持各客户端现状（桌面端文件夹跟随「排在最前的线程」移动。移动端按保存的文件夹顺序）。
- Attention inbox（「需要处理的内容」的另一个列表）的排序不变。
- 不要每条消息都把 `updatedAt` 写入 `bots.json` 或 `groups.json`。启动时的回填，对每个发生变化的文件只保存一次。
- 文件夹内的线程顺序在三个客户端中一致（先置顶，再按更新时间从新到旧）。文件夹之间的顺序，桌面端和 iOS 跟随该文件夹中排在最前的线程移动。未整理的线程排在文件夹之后。Android 保持保存的文件夹顺序。
- 铃铛和 Updates 保持注意顺序。折叠侧边栏的「其他线程」中，除需要注意的之外也保留置顶。
