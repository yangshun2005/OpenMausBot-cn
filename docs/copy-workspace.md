# 将这台电脑复制到这里

桌面应用中的一个操作，会把这台电脑的工作区复制到用户拥有并在应用中添加的服务器：运行 `openmausbot serve` 的 VPS 或家用服务器、`service install`、Docker 或 Podman 安装、通过其远程访问连接的另一台桌面，或他们的 OMB Cloud。每个目标都走同一套代码（桌面上是 `electron/cloud-move.mjs`，接收服务器上是 `server/cloud-move-http.ts` 和 `server/cloud-move.ts`）。Cloud 只额外提供套餐包含的内容：一个无需会话即可让应用登录的 Admin，以及一块可扩容的磁盘（docs/cloud-pro.md，"将这台电脑复制到你的 Cloud"）。

这是复制；电脑上的任何东西都不会改变。聊天记录在这里、且仅在这里于机器之间传输，因为用户主动要求如此。密钥永不传输。设置 → 备份的导出和导入仍然保留，用于灾难恢复，以及附近没有桌面应用的服务器。

名称中仍带 "cloud"（`/api/cloud-move`、`.backups/cloud-move`、`.backups/cloud-previous`、`cloud-move-restores.json`、`cloudMove` 桥接及其 `cloudMove.*` 字符串）：已在运行的 Cloud 会在这些路由上应答，并把它们的换回备份保存在这些文件夹中。

## 入口位置

- **添加服务器之后立即出现。** 在设置 → 服务器中点击 **连接** 后，应用会打开该服务器自己的页面。如果服务器是空的（最多只有初始机器人，没有房间，没人聊过天），这台电脑有自己的工作内容，复制能装下，且没有阻碍（见下文），页面会显示一张卡片：**从这台 Mac 引入你的机器人和聊天**（其他地方显示为"这台电脑"），带有 **复制** 和 **暂不**。暂不将对该服务器永久隐藏此卡片。较早添加的服务器在下次打开时、只要仍为空就会显示它。在设置清单已弹出的 OMB Cloud 上，同样的提议改为清单的第二步（docs/cloud-pro.md）。那里的 **复制** 会把窗口切换到这台电脑，打开设置 → 服务器并展开该服务器的面板，用户在那里开始复制（见下文"安全"）；在用户自己的 OMB Cloud 上，经 Admin 验证后，会立即开始复制。
- **设置 → 服务器 → 将这台电脑复制到这里**，位于每个已保存服务器的行上（不含"这台电脑"），以及 **设置 → MausBot Cloud** 下 My Cloud 就绪后的条目。两者打开同一个面板：大小和计数（这台电脑自己服务器上的 `GET /api/cloud-move/estimate`）、说明 API 密钥和登录信息留在本机、以及 **复制到 {server}**。当服务器已有机器人或聊天时，按钮显示 **用这台电脑的机器人和聊天替换 {server}**，面板说明其现有内容会被替换、先在它上面备份、并由 **将 {server} 换回** 恢复。当它已保存一份用于换回的备份（更早的一次复制）时，面板说明再次复制会把当前内容备份到该备份的位置并删除 {date} 的那份，按钮显示 **替换 {server} 并删除其 {date} 备份**。没有确认对话框。
- **设置 → 备份 → 从这台电脑导入**，在桌面应用中打开的服务器上，位于从文件导入旁边。它与卡片是同样的提议、同样的状态和消息，其 **复制** 会在这台电脑上打开同一个面板，无论服务器是否为空。在浏览器中、在这台电脑自己的服务器上、以及与他人共享的服务器上，它会被隐藏。

复制完成后，应用会打开目标服务器，其页面会说明带来了什么、以及哪些还不能在那里运行（例程到达时处于暂停状态；手机仍与这台电脑配对），直到点击 **完成**。

## 每个状态，一条消息

`moveView`（`src/components/CloudMove.tsx`）是复制状态到用户所见内容的唯一映射：一句话和一个下一步。复制无法开始的原因（`moveBlocked`，引擎在导出前也会应用）和因该原因失败的复制共用同一个代码，因此它们的显示和操作一致。

| 状态 | 消息 | 下一步 |
|---|---|---|
| 就绪 | （大小，哪些留在这里） | 复制到 {server} / 替换 {server}… |
| 进行中 | 正在上传到 {server}… 等，带字节数 | 停止复制（直到开始替换） |

| 未以所有者身份登录（客户端范围配对） | 此应用未以所有者身份登录到 {server}。用所有者代码（`openmausbot pair`）重新配对，然后复制。 | 打开 {server} |

| 重启后未恢复 | {server} 尚未恢复。如果它没有自行重启，请在那里启动 OpenMausBot；它启动时会完成复制的安装。 | 打开 {server} |

## 传输什么，保留什么

正是工作区备份所携带的内容（`server/workspace-backup.ts`、`server/workspace-backup-policy.ts`）。永不传输：API 密钥、提供商和 MCP 连接、引擎登录（`~/.claude`、`~/.codex`、服务器的 `providers/`）、已保存的凭据、配对、已配对设备和会话（包括会话注册表的打开标记）、服务器身份、缓存、已下载的工具和运行时文件。也永不传输此应用的 Cloud 登录或它借出的内容：两者都存放在桌面应用自己的存储中。未发送的草稿和窗口偏好留在本机。

目标保留自己的内容：其配置的每个连接部分（引擎和 API 密钥、中继、登录允许列表）、其会话和配对、其引擎登录、其电脑共享开关、及其环境。与任何恢复一样，例程、Webhook 和定时调用到达时处于暂停状态，队列中的内容不会运行。使用了目标所没有的引擎或密钥的机器人会在那里请求一个；指向工作区之外项目文件夹的机器人保留该路径。

## 如何复制

1. **主进程在那里证明所有者身份**，每个目标调用一次 `grant()`，并打开自己的会话：
   - OMB Cloud：Admin 为已登录的所有者打开一个一次性配对窗口（`pairHome`），因此即使这里从未打开过 Cloud 也能工作。
   - 任何其他服务器：窗口在那里的自身会话（其 `/pair` 页面设置的 cookie，通过 Chromium 的 cookie jar 读取）必须是具有 admin 范围的已登录会话（`GET /api/auth/session`）；它铸造一个一次性所有者代码（`POST /api/auth/pairing {scopes: ["admin", "client"]}`，使用服务器自己的 Origin，`mintOwnerCode`）。

   授权必须指明目标自己的 origin。主进程在 `/api/auth/pair` 兑换该代码，获得仅保存在内存中的 bearer token，标记为 "Copy from desktop"，并在复制结束时登出该会话。窗口的 cookie 绝不是复制的凭据：登出它会把窗口也登出。
2. **在导出任何内容之前拒绝**：应答 404 的服务器（来自更早版本，`outdated`）、共享的服务器（403 `shared_workspace`），以及按设置所显示的 `moveBlocked`，这台电脑自己的服务器（相同的 `environmentId`）和比这台电脑旧的服务器（`outdated`，按暂存所用的 `appVersion` 规则：它只会在整个上传之后才拒绝更新的备份）；然后是繁忙的、空间不足的，以及从已验证 Cloud 自己的页面发起的、有工作内容的 Cloud（`not_empty`）。
3. 这台电脑的服务器用随机密码导出其加密备份，遵循机器人先完成其回合的常规规则，主进程将其复制到私有临时文件并计算哈希。
4. `POST /api/cloud-move/upload {sha256, bytes, files}`：最多 10 GB 数据或 100,000 个文件（`413`）；上传所需空间的三倍（上传、其解密副本、其暂存文件），加上服务器自身工作区的两倍（它先做的备份），加上 256 MB（否则 `507`，带 `freeBytes` 和 `neededBytes`）。早先上传已存储的分片计为可用空间。
5. 16 MB 的分片（最多 64 个）：`PUT /api/cloud-move/upload/<sha256>?offset=n`。已存储的分片会再次被接受而不写入；任何其他偏移应答 `409` 并带 `received`。主进程以退避重试，并从服务器所处位置继续。服务器绝不会对分片应答 `413`（超过其限制的分片得到 `411`），因此 `413` 是它前面的代理（nginx 默认允许 1 MB）：分片减半，直到 512 KB，连这个都拒绝的代理会以 `proxy_limit` 结束复制，并指明大小和要调高的设置。失败的上传保留其归档 30 分钟，因此再次复制会继续它；服务器保留已存储的分片一天。
6. `POST /api/cloud-move/preview {sha256, password}`：服务器校验 SHA-256 并将其作为普通备份暂存，这会在解析任何内容之前认证整个文件。
7. `POST /api/cloud-move/restore {id}`，在维护门内：先备份服务器的工作区（换回），提交恢复，服务器以代码 75 退出（见下文）。启动时会在加载任何其他内容之前安装该恢复。预览、恢复和撤销应答 `202`，并作为应用在 `GET /api/cloud-move` 中跟踪的任务运行。
8. 主进程等待服务器报告该恢复已安装（`lastRestoreId`），登出其会话，并在窗口中打开该服务器。

在第 7 步之前停止，或之前的任何失败，都会请求服务器丢弃复制暂存的内容（`POST /api/cloud-move/discard`）。已存储的上传分片会保留。

## 换回

在复制替换服务器工作区之前，该工作区会备份到服务器自己磁盘上的 `.backups/cloud-previous`，任何备份都不包含它，任何恢复都不替换它；其随机密码保存在旁边。除非是全新服务器的，否则它会在这台电脑的设置中作为 **将 {server} 换回** 提供。换回（`POST /api/cloud-move/undo`）是反向的同一次恢复：服务器当前的内容成为要换回的目标，因此换回本身也可以被换回。再次复制会用服务器当时内容的备份替换该归档，因此更早复制之前它保存的内容会被删除；面板会在复制开始前说明这一点并带日期。该归档是保留的唯一撤销点：每个服务器启动时，一旦其恢复安装完成，就会删除复制的安全副本和暂存文件（`tidyCloudMoveStorage`，只触碰复制记录过的恢复）。从设置 → 备份进行的恢复会保留其安全副本。

## 重启，按启动器

`server/restart.ts` 保存唯一的代码 `RESTART_EXIT_CODE = 75`（"重新启动我"），以及每个启动器都询问的唯一规则 `restartPolicy().again(code, stopping)`：仅在 75 时重新启动服务器，最多连续 5 次（运行满一分钟会重置计数）。

| 启动器 | 退出码 75 时 |
|---|---|
| OMB Cloud（`server/cloud-home-start.ts`） | 只重新启动服务器 |
| 桌面应用自己的服务器（`electron/server-supervisor.mjs`） | 任何退出后都重新启动它 |
| 终端中的 `openmausbot serve` / `npx openmausbot`（`serveUntilStopped`、`server/cli.ts`） | 在同一进程中再次运行 `serve`，无需新的配对代码或浏览器标签；隧道、Tailscale 或域名地址保持不变 |
| systemd `service install`、fleet、launchd | 它们运行 `openmausbot serve`，因此是同一个循环 |
| Docker（`Dockerfile`）、Podman（`deploy/podman/Containerfile`） | `node dist-server/server-launcher.js`（`server/server-launcher.ts`）再次启动 `index.js` 并传递 SIGTERM，因此容器以及共享其网络的 Caddy 永不宕机 |
| 其他（手动 `node dist-server/index.js`、自定义管理器） | 保持停止；恢复已提交，并在下次启动时安装 |

应用等待服务器恢复 10 分钟，然后以 **打开 {server}** 提示。

## 安全

自托管服务器关于自身所说的一切都是它的一面之词：此应用在那里的会话是所有者会话（`/api/auth/session`）、它铸造的配对代码、它是空的、它的版本和身份。别人运行的服务器（同事的、用客户端代码加入的、或被修改过的）可以声称这一切。因此那面之词只决定向用户显示什么，绝不决定这台电脑的工作内容是否被发送：

- **只有这台电脑自己的窗口才能向服务器发起复制。** 这台电脑的页面按 id（或 "cloud"）指定已保存的服务器并在那里发起。服务器自己的页面不指定任何东西，且只就自身被应答，前提是它是主窗口主框架中窗口的活动服务器（`moveSenderDestination`）；其 **复制**（仅来自用户的点击，`navigator.userActivation`）会让主进程把窗口切换到这台电脑，打开设置 → 服务器并展开该服务器的面板（`openWorkspaceSettings(id, "copy")`），不发送任何内容。用户在那里开始复制，服务器被指明，其大小和要替换的内容也一并显示。那是应用自己的设置，不是批准提示。除已验证的 Cloud（见下文）外，任何页面都无法开始发送这台电脑的工作区。剩下的情况：用户仍可在这台电脑的设置中选择复制到别人控制的服务器；面板会在其行和地址下方指明它。
- **用户自己的 OMB Cloud 是唯一的例外。** 此应用通过 Admin 用用户的 OMB Cloud 登录来验证它，独立于 Cloud 的一面之词（`cloudPageSenderAllowed`：Admin 的 origin，作为窗口的活动服务器打开），因此其卡片和设置清单会立即开始复制，且只复制到空的 Cloud（`requireEmpty`，导出前 `not_empty`）。替换和换回仍在这台电脑的设置中。
- **那里的所有者会话。** 主进程用目标那里其所有者会话铸造的代码登录（Cloud 用 Cloud 的 Admin）。每个接收路由都需要具有 admin 范围的已配对会话；客户端范围的设备和裸回环请求会被拒绝。这能挡住该服务器上的其他人；它不为服务器背书。
- **服务器页面能了解到什么。** 询问自身时，服务器页面会得到这台电脑的计数和大小（机器人、房间、聊天、字节、例程）以显示在其卡片上，绝不会得到这台电脑的环境 id 或它持有的任何内容。
- **绝不复制到共享工作区。** 托管的组织工作区，或电子邮件登录允许所有者之外的人进入的自托管服务器（成员、第二个 admin 地址，或整个 `@domain`：`sharedSignIn`、`workspaceShared`），会拒绝每个接收路由（403 `shared_workspace`）：替换会抹掉他们的工作。仅所有者自己的地址（`openmausbot access add you@example.com`，用于从浏览器登录）不算共享。
- 上传受其声明大小、每分片限制和备份自身限制的约束。该包就是工作区备份：凭据按路径和配置允许列表被排除，并在暂存时再次检查。`server/cloud-move.e2e.test.ts` 提供桌面密钥、驱动环境、工作区凭据和提供商登录，将其复制到真实的 Cloud 和真实的自托管服务器，并扫描其卷上的每个文件。
- 任何内容都不记录请求体、密码、文件名或包内容。

## 尚未覆盖

- 复制在主进程中使用 Node 的 `fetch`，而非窗口的会话：位于系统代理或企业 CA 后面的服务器在窗口中可用，但复制会以 "could not reach" 失败。
- 版本检查连补丁更新的桌面也拒绝（暂存的规则）：请先更新服务器。
- 未手动运行：launchd 节流、Podman、Windows 任务计划程序。
- 在大分片上断开连接而非应答 413 的代理，看起来像连接断开：复制会重试该分片，然后提示上传持续失败。
