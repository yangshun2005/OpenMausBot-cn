# Agent 通知与主动性 QA

OpenMausBot 将**主动性视为显式触发器**，而非隐藏的心跳。Bot 可以在 Auto 模式下继续执行活动任务，可以由 Routine 或 Webhook 启动，并且在其引擎和配置文件允许时协调对等节点。此变更不会添加后台轮询来凭空创造工作，也不会在未配置上述路径之一的情况下发送消息。

## 通知策略

harness 是中断策略的唯一所有者。禁用通知的 Bot 保持静默。否则它可能发出：

- **需要批准**或**有问题**，当任务因用户而阻塞时。
- **需要你介入**，当计算机任务需要接管时。
- **已完成**，仅当有非空结果需要汇总时。
- **Routine 失败**，当计划或手动 Routine 运行无法完成时。

每条通知都携带 Bot ID 和确切的任务线程 ID。点击必须选中该 Bot **并切换到该任务**，包括 Routine 的分离任务；打开恰好处于活动状态的任意任务是失败的。

当窗口已获得焦点时，桌面通知被抑制。iOS 应用在运行时可以呈现实时或重放的通知，并在点击通知时使用相同的 Bot/任务目标。唤醒已终止的 iOS 应用仍需要未来的 APNs 中继；仅靠本地网络或 VPN 连接无法提供已关闭应用的投递。

## 手动发布检查

使用两个 Bot 运行以下检查，一个启用通知，另一个禁用通知：

1. 将桌面窗口置于后台。完成一个普通任务并确认收到一条结果通知。点击它并验证确切的任务打开。
2. 触发一次批准和一个问题。确认它们的文案、点击目标，以及任务结束前不会出现重复的完成通知。
3. 手动运行一个 Routine，然后创建一个受控的失败运行。确认回执显示分离任务，且失败恰好生成一个警报。
4. 对该 Bot 禁用通知后重复上述步骤；聊天和运行回执应更新，但不出现系统警报。
5. 在 iOS 上，点击一个非活动 Routine 任务的实时/重放通知。确认应用在导航前切换服务器端活动任务。
6. 分别演练 Auto 模式、Routine 和 Webhook。验证每个都有可见的发起用户/已配置触发器，且没有未配置的心跳启动工作。

实时提供商、操作系统权限、后台化和 APNs 行为无法仅通过单元测试证明，仍属于已签名的桌面/iPhone 发布检查的一部分。
