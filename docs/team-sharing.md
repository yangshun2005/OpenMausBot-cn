# 共享整个团队

**共享团队…** 将一个团队保存为单个文件（`<team>-<version>.openmaus.json`）。
其他人可在 **模板 → 导入** 中添加，或由组织在 Admin → Packages 中上传，其桌面端从 **模板 → 来自 {Organization}** 添加（[org-library.md](org-library.md)）。可从侧边栏的团队菜单（右键点击团队名称）打开，或从 **模板 → 共享** 打开。

## 文件中包含的内容

- **机器人。** 每个机器人的名称、标题和描述、常驻指令、颜色和吉祥物，以及图片（缩小至最大 256 × 256 和 64 KB；对话框在图片总量约 2 MB 后停止添加）。
- **技能。** 默认包含团队机器人上的所有技能，或你勾选的技能。仅传输 `SKILL.md` 文本，绝不包含脚本或其他文件。一个文件最多包含每个机器人 30 个技能、每个团队 60 个技能，且每个名称仅一个技能。未选择时，对话框放入能容纳的技能（优先已启用的技能），其余列在 **已排除** 下，包括两个机器人持有但内容不同的同名技能。技能框随后以已放入的技能为初始勾选状态，减去机器人因超过 30 个而不得不排除的技能（即使另一个机器人的副本已放入），因此取消勾选任何框始终是可行的选择。勾选超过容量时，会说明原因并保留所有技能框，以便你更改选择。
- **剧本**、**群聊**（成员及默认回复者）和团队的**共享指令**。
- **例程**，包括群聊目标。它们始终以暂停状态到达。
- **幕僚长。**
- **连接。** 对每个机器人使用的远程 MCP 服务器：其地址及其所需值的名称（例如 `Authorization`）。值本身绝不传输。托管服务器通常将密钥保存在地址本身中，因此地址会丢失任何登录部分和 `#fragment`，并保留其查询和 `;matrix` 参数名，值清空（`?key=`、`;key=` 以及路径段内的 `key=`）。任何看起来像密钥的路径段、参数名或子域标签（最后两个主机标签左侧的任何内容）都会被替换为 `redacted`。当 `%XX` 转义解码后，某部分包含 16 个或更多字母、数字、`-` 或 `_` 的连续串且混合字母和数字，或 24 个或更多字母或数字的连续串（如令牌、十六进制密钥或服务器 id）时，该部分看起来像密钥。由连字符连接且带短数字的单词，如 `github-mcp-server-2024`，保持原样。该规则刻意宽泛，因此对话框在保存前列出每个连接的完整地址，并指出任何被更改的地址。
- **起始笔记。** 每个机器人的 `MEMORY.md` 和主题笔记。**包含起始笔记** 默认勾选，因为团队是整体共享的；如果笔记包含你的私人细节，请取消勾选。每日日志绝不包含。
- **连接器要求**（团队期望哪些已连接应用），仅作为标签。
- **你的新建机器人默认值作为预设**，仅当你勾选 **将我的新建机器人默认值作为预设包含** 时：其名称、外观、常驻指令、技能和（含起始笔记时）笔记，绝不包含其模型、文件夹、计算机、审批级别或已连接应用。参见 [presets.md](presets.md)。

## 文件中绝不包含的内容

聊天历史、密钥和密码、模型选择、计算机，以及谁可以看到每个机器人。文件格式没有这些的任何字段。在此计算机上运行命令的本地 MCP 服务器被排除，例程附件也被排除。

文本仍可能包含某人输入的机密。在写入文件前，每个文本部分都会用应用用于日志的相同检测器检查。任何看起来像密钥或密码的内容都会被替换为标记，对话框列出哪些部分被更改。Admin 上传会再次运行相同检查，并拒绝仍包含此类内容的文件。

对话框在保存前显示文件确切包含的内容（由服务器从同一导出中计数），保存后显示被移除或排除的内容。没有确认步骤：**保存文件** 即是决定。

## 版本与身份

团队首次共享时获得一个包 id（来自其名称），每个机器人、群聊和例程获得一个键。同一团队的后续共享复用它们，即使重命名团队或其任何内容，并建议下一个版本（1.0.0，然后 1.0.1，……）。首次从共享文件添加的团队保留该文件的包 id 和机器人键，因此"导入已发布的发布版本、编辑、再次共享"会生成同一包的下一个发布版本。记录保存在数据文件夹中的 `published-teams.json`。

## 添加共享团队

导入是增量的：一切都会成为新团队中的新记录（名称被占用时编号）。文件中的任何内容都不能更改你已有的机器人、群聊或团队。

- 机器人以 **Ask** 启动，无已连接应用访问权限，使用安装的默认模型。文件中的建议审批级别会被记录，绝不应用。
- 技能以**关闭**状态到达；例程以**暂停**状态到达。
- 每个连接成为一个新的 MCP 服务器，**关闭**且值为空，以连接命名（`crm`，或当 `crm` 已被占用时 `crm-2`，因此它绝不会拾取你已有的凭据）。你组织的 MCP 策略仍然适用；被拒绝的连接会被列出，团队其余部分仍会添加。在 **插件 → MCP 服务器** 中完成连接。
- 起始笔记通过常规记忆写入器写入一次。
- 文件中的预设机器人出现在 **新建机器人** 下的 **已导入预设** 中；由预设创建的机器人其技能为关闭状态（[presets.md](presets.md)）。
- 预设文件（技能和预设，无机器人）将其预设添加到新建机器人，别无其他。仅含技能的文件在此无可添加内容，会被拒绝并指向组织货架（**模板 → 来自 {Organization}**，参见 [org-library.md](org-library.md)）。

如果任何步骤失败，导入创建的所有内容都会被移除。

## 文件格式

`openmaus.package` 版本 2，定义于 `shared/package-format.ts`，这是应用、导入预览和 Admin 共同用于验证的唯一模块。它仍可读取版本 1 文件（JSON 和 BotMRR Markdown 剧本）。较旧的应用会以其现有的"不支持"消息拒绝版本 2 文件；Admin 可为其生成版本 1 下载。文件最大 4 MB。示例文件及其预期哈希位于 `shared/package-fixtures/`。

HTTP 路由为 `POST /api/teams/export`，请求体为 `{"format":"package","version":2,"team":"Sales desk"}`（admin 范围）。可选字段：`name`、`tagline`、`summary`、`release`、`notes`、`skills`（`"all"` 或名称列表）、`includeMemory`（通过 API 时默认 `false`）、`avatars`（按机器人 id 的数据 URL）和 `dryRun`（计数但不记录键）。响应为 `{document, filename, redacted, skipped, summary, choices}`。使用 `skills: "all"` 时，导出放入能容纳的技能，其余列在 `skipped` 中；名称列表要么精确共享，要么被拒绝。版本 2 请求体的每个 `400` 还携带 `choices: {skills}`（团队机器人上的所有技能名称），以便客户端提供不同选择。`includeDefaultsPreset: true` 添加新建机器人默认值预设，`kind: "library"`（而非 `team`）保存预设文件；两者在 [presets.md](presets.md) 中描述。不带 `version: 2` 的请求体保留原始的整安装 Markdown 导出。
