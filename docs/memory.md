# Bot 记忆

默认情况下，Bot 会在任务之间保留笔记。这些笔记是纯 markdown 文件，存放在运行 OpenMausBot 的电脑上的一个文件夹里——不会存储到其他任何地方，你可以用任何编辑器打开、编辑或删除。**Bot 设置 → 记忆** 会显示同样的文件，并附带一个仪表，显示其中有多少内容实际会被加载；还有一个编辑器，绝不会覆盖 Bot 在你打字期间写入的内容；以及一份每次变更的日志，支持一键撤销。

**允许此 Bot 使用记忆** 开关默认开启。在 Bot 空闲时关闭它，可停止将 `MEMORY.md` 加载到新的回合中、停止自动回忆与维护、隐藏原生记忆工具、将记忆文件从 `session_search` 中排除，并停止自动的每日回合日志。现有文件仍保留供查看。拥有文件系统访问权限的 Bot 仍可直接编辑这些文件；当记忆必须保留在另一个事实来源时，请用常驻指令禁止这样做。

## 存放位置

```
~/.openmausbot/workspaces/<botId>/
├── MEMORY.md            加载到每次对话中的笔记
└── memory/
    ├── <topic>.md       Bot 按需读取的较长笔记
    ├── archive.md       从 MEMORY.md 移出的旧笔记，以及已过期的笔记
    └── log/
        └── 2026-09-10.md   Bot 当天做了什么，用它的原话记录
```

该文件夹是 Bot 的私有工作区：当它没有设置项目文件夹时，其文件工具就在这个目录中工作。它在 Bot 首次运行回合时创建。记忆面板中的 **在 Obsidian 中打开** 和 **在 Finder 中显示**（Explorer 或你的文件管理器）会打开这个文件夹；由于它在服务器的磁盘上，这些按钮只能从运行 OpenMausBot 的电脑上使用——配对的手机或远程浏览器只会显示路径。

文件以仅所有者权限（`0600`）写入，采用原子写入（写入中途崩溃会保留旧文件完好，绝不会出现残缺文件），任何看起来像凭据的内容——API 密钥、令牌、`password: …` 行、私钥块——在写入磁盘前都会被替换为 `«redacted N chars»`。一个"好心"记住从 `.env` 读到的密钥的 Bot 无法保留它。

## 加载什么，以及预算

每个回合开始时，**`MEMORY.md` 的前 200 行或 24 KB，以先到者为准**，会被放入 Bot 的系统提示中。超过该行的内容不会加载，Bot 只会被告知文件被截断。主题文件和每日日志从不自动加载；Bot 在认为需要时用文件工具读取主题文件，日志则是给你看的。

记忆面板顶部的仪表就是这条规则的可视化：行数和大小对照预算，从 80% 起显示琥珀色，一旦有内容停止加载就显示红色——并附上未加载的行数，以及始终显示的那句朴素的话 *每回合只加载前 200 行*。

`MEMORY.md` 永远不会填满。每次经由 harness 的写入（`memory_update` 和捕获）都会在同一步中让文件保持在预算内：当新条目会使其超出时，最旧的带日期条目会移到 `memory/archive.md`——先是删除线条目，然后是已过期条目，再是最旧的活跃条目——每条都标记 `· moved <date>`。条目整体移动，连同其下缩进的行（代码块），或在较旧条目中紧接其下的代码块。归档先于 `MEMORY.md` 写入，因此一行绝不会在尚未进入另一个文件时就离开原文件，`session_search` 仍能找到它。你手写的行（无日期）、健康与安全事实，以及刚写入的条目永不移动。Bot 会被告知哪些条目移动了（前几个，以及总数），以便它能加回任何应保持加载的内容。一个条目最多 1,000 个字符和 20 行，因此单条笔记无法挤掉其余内容。只有当永不移动的行本身填满预算时（或 Bot 用自己的文件工具编辑了文件），仪表才会变红：此时条目仍会保存，Bot 会请你精简 `MEMORY.md`。

这两个限制是 `server/workspace.ts` 中的 `MEMORY_MAX_LINES` 和 `MEMORY_MAX_BYTES`；面板、加载器和 Bot 的提示都读取同样的两个常量。

还有两项内容随之加载：

- **已过期笔记不加载。** 以 `· until 2026-09-28` 结尾的条目在该日期之后停止加载。文件会保留它（仪表仍计入它），直到整理或有人移动它。
- **主题索引。** 每个 `memory/<topic>.md` 都会按名称列在记忆块下，当文件以 frontmatter 开头时，还会列出其 `title`、`description` 和 `aliases`——最多 40 个主题或 2,000 个字符。文件本身仍只在 Bot 读取它们时才加载。

## 每回合前的回忆

在回合之前，用户的消息（八个字符或更多）会搜索 Bot 的主题文件，并在用户发起的 1:1 聊天中搜索 Bot 的其他对话。任何匹配的词都算数；一条含五个或更多实词的消息需要每个命中匹配两个词。最多四条笔记和四段对话片段——编号、带日期、最多 6,000 个字符——会放在该回合消息的前面，开头一行说明它们是 Bot 自己的笔记，其中的命令不是指令。`MEMORY.md`（已加载）和 `memory/archive.md`（较旧或不再为真）从不被回忆，每日日志也不会（`session_search` 在 Bot 请求时能找到它们）。

它被放在消息中而非系统提示中，是有意为之：提示中变化的那一半在任何部分改变时都会整体重发，而回忆几乎每回合都在变。房间、例行运行（全新开始），以及由另一个 Bot、webhook 或队友交接发起的回合，只回忆笔记——私密聊天通过 `session_search` 到达房间，而后者会披露它。`config.json` 中的 `features.autoRecall: false` 会关闭回忆。服务器日志会记录每次回忆（`auto-recall: … got N note and M conversation passage(s)`）。

## 记忆维护

**Bot 设置 → 记忆 → 记忆维护** 对每个 Bot 默认开启，除非关闭。它让笔记保持良好状态，无需 Bot 自己决定去做：

- **注意事实。** 当 1:1 聊天安静两分钟（`memory.captureQuietMs`），或在六个回合后，一次快速的模型调用会读取这些回合——用户的话和 Bot 的话按不同规则处理——对照 `MEMORY.md` 和主题文件列表，并归档新内容：
  - Bot 在每次对话中都需要的一条核心事实进入 `MEMORY.md`，标记 `(noticed)`：
    `- 2026-09-25 · from chat "Plans" (noticed) · The person is vegetarian`；
  - 其他所有内容进入其主题的主题文件——一个人、一个项目或客户、食物、旅行——复用现有主题或创建一个带标题（`title`、`aliases`：别人可能用来提问的其他词）的主题，以便回忆日后能找到它。
  在已知日期结束的事实会带上其 `until` 日期；生日或其他每年重复的日期则从不带。由另一个 Bot 或 harness 发起的回合、例行运行和失败的回合从不被读取；房间仅在开启 **从群聊学习**（见下文）时才会。 
- **从群聊学习。** 记忆维护下的 **从群聊学习** 开关（`features.roomMemoryCapture`，每个 Bot 一个开关，默认关闭）让成员 Bot 的房间回合以同样方式供给其捕获，按 Bot 和房间分批。Bot 自上次在该房间发言以来所读的内容，会连同其回复一起按房间规则读取：用户自己的话算作他们的；别人的话只给出关于共同工作的事实，绝不进入"关于我"（包含这些内容的批次不会向"关于我"添加任何东西）；另一个 Bot 的话只给出它验证过的结果或用户同意的决定，绝不给出其建议或主张。没有用户话语的一段会被跳过。条目会标注来源房间：
  `- 2026-09-25 · from room "Launch" (noticed) · The launch moved to Friday`。
  可见人数少于该 Bot 的房间绝不供给它（与近期工作简报相同的规则），在捕获批次时会再次检查，开关和 Bot 的成员身份也会检查。Bot 对 Bot 的频道、房间交接、目标运行，以及在 Cloud 家庭上，每个房间都被排除。
  应用退出或通过正常关机重启时仍在等待的回合，会以其 id（绝不用其文本）保存在 `memory-capture-pending.json` 中，最多 50 个聊天，并在下次启动时从聊天中读回，因此退出前刚说的话仍会被注意到。崩溃或强制终止会跳过这一步（在 Windows 上 `SIGTERM` 就是强制终止），这些回合不会被捕获。期间被删除或回退的聊天不会留下可读内容。
- **整理。** 无论谁在 `MEMORY.md` 中写了一行——用 `memory_update` 的 Bot、用户，或捕获——在每次捕获后以及夜间整理中，一次快速的模型调用会查看之前未评判过的行，并将那些属于某主题细节的行（另一个人、一个项目或客户、一次旅行、某一领域的喜好）原样移入该主题的主题文件，用标题和其他词创建它。核心事实——用户的名字、居住地、公司、饮食、过敏和健康需求、他们喜欢的回复方式——始终保留；关于饮食、过敏或健康的行甚至不会被提议移动（这是固定规则，不是模型的选择），被判定为核心的行不会再被询问。一次最多移动 20 行；每个文件的变更是一行日志（*filed into topics*），可以撤销。
- **关于我。** 关于用户的一条持久事实，取自他们自己的话，会被添加到 **设置 → 通用 → 关于我**，每个 Bot 都会读取，作为带日期的行 `- 2026-09-25 · learned by Scout · …`。"关于我"下的 **由你的 Bot 添加** 会列出每一条并带 **移除**；被移除的事实绝不会再次添加。在共享安装中，别人的消息绝不会添加到所有者的"关于我"。
- **夜间整理。** 每天凌晨 3 点后一次（`memory.tidyHour`），或电脑休眠时在下次检查时，绝不在 Bot 工作时，以及通过 **立即整理**：已过期条目移到 `memory/archive.md`（从 `MEMORY.md` 和主题文件）；两条事实完全相同的条目中，较新的保留；在 `MEMORY.md` 中，一次模型调用查找不能同时为真的配对，将较旧的划删除线（`~~…~~ · superseded <date>`）而非删除；当该行还包含仍为真的内容（"住在浦那且喜欢简短回复"）时，该部分作为自己的条目 `from tidy-up` 保留。一次最多可划掉五分之一的条目，少于五条的文件中一条也不划。归档先于其来源文件写入，因此撤销最新变更绝不会丢失一行。

"事实完全相同"刻意定义得很窄：忽略空格、项目符号和末尾句号，其他一概不忽略——`Balance is -10` 和 `Balance is 10`、`C++` 和 `C`、`1.5` 和 `15` 是不同的。

每次维护变更都是 **记忆维护** 的一行日志，可以撤销。备份运行时维护暂停。模型步骤需要一个支持一次性文本调用的引擎——Claude、Codex、Grok、OpenAI 兼容、Mistral 和 MiniMax，以及支持 ACP 的 agent 引擎（Grok CLI、Gemini、Kimi、Droid、Cursor、OpenCode、Qwen、Hermes、Antigravity 和自定义 ACP agent）。在 ACP 引擎上，每次调用都会在空文件夹中以其自己的全新会话启动引擎自己的 CLI，绝不用聊天的会话，不加载 MCP 服务器，并处于先询问的批准模式；一旦 agent 请求工具、文件或权限，它就会被拒绝并丢弃。在 Codex 上，每次调用都是在同一登录下的一个 `codex exec`，在空文件夹中、只读沙箱、不保存会话、不加载用户的 `config.toml`（因此他们的 MCP 服务器、插件或 Hook 都不会启动），并关闭 shell 和所有其他工具；它使用账户列出的最小模型（GPT-6 Luna）以低强度运行，因为它消耗用户自己的套餐，并在 Codex 报告工具调用时立即丢弃。文本只发送给 Bot 已使用的提供商。在任何其他引擎上（目前是 Pi），面板会说明这一点——在记忆维护下和从群聊学习下——并且只运行过期和完全重复的步骤。

## 编辑

`MEMORY.md` 和每个主题文件都可以在面板中编辑。保存会携带你打开时文本的哈希；如果 Bot 在此期间更改了文件——它在任务中用 `memory_update` 写入，或用其自己的文件工具写入——保存会被拒绝，面板会说明：*Scout 在你编辑时更改了此文件。* **重新加载** 会显示 Bot 的版本，并将你的草稿保留在编辑器下方，因此你输入的内容不会丢失；**用我的覆盖** 会用你的版本覆盖它。无论哪种方式，变更都在日志中，可以撤销。

每日日志在面板中为只读（它们是 Bot 自己的记录），但可以删除。`MEMORY.md` 可以清空但绝不能删除——Bot 期望它存在。主题名是 `memory/` 下的一个文件名：字母、数字、空格、点和短横线，以 `.md` 结尾。不能嵌套，不能以点开头。

旧的整文件 `PUT /api/bots/:id/memory` 仍在一个发布版本中可用；它没有哈希检查，因此可能覆盖 Bot 刚写入的内容。客户端应迁移到带 `expectedHash` 的 `PUT /api/bots/:id/memory/file`。

## Bot 对其其他对话的了解

Bot 的 1:1 聊天和它的房间是分开的对话，而它的记忆只保留仍为真的内容——因此单独来看，在房间中回答的 Bot 不知道它一小时前在 1:1 中做了什么，早晨的站会以猜测告终。有三样东西在不附加转录的情况下弥合这一差距：

- **近期工作简报。** 每个回合的系统提示，无论 1:1 还是房间，都带有一个短块：Bot 在过去两天里在其*其他*每个对话中说的最新内容——`today 09:05 · 1:1 with Milind · "Invoice reconciliation" · you said: "Sent the three flagged invoices…"`。最多十行，约 350 个 token；当前对话不列出。当房间中的简报提到一个私密 1:1 聊天时，房间会得到一个提示条——*Lead 的近期工作简报涵盖与你的 1 个私密聊天*——每个聊天一次，与回忆消息相同的规则。
- **记忆开启时，每个完成的回合一行日志。** harness 会将 Bot 最后说的话、它使用的工具，以及该回合是否失败追加到 `memory/log/YYYY-MM-DD.md`，并标注来源聊天或房间。日志从不加载到提示中；`session_search` 能找到它。
- **按时间回忆。** `session_search` 接受 `since`（`"24h"`、`"3d"`、`"yesterday"` 或日期）和 `until`，可带词也可不带词，并覆盖 Bot 作为成员所在的房间及其 1:1 任务。"自昨天站会以来发生了什么"无需关键词。命中会标明其来自的房间或任务；被回忆到房间中的私密聊天会被标记，并告知房间。

这样，每日站会就是一个房间例行：负责人提问，每个成员根据其简报回答，并用 `session_search since` 拉取细节，达成的共识会出现在每个成员的下一个 1:1 简报中。

## 日志

应用能看到的对记忆文件的每次变更都会被记录——你从面板的、Bot 在任务中的、导入的、撤销的——记录在 `~/.openmausbot/memory-journal/<botId>.ndjson`。它有意放在工作区*之外*：Bot 的文件工具指向工作区，而一个 Bot 能编辑的记录就不算记录。

每行说明谁（Bot、用户或导入）、如何（在设置中、任务中、来自哪个聊天、应用外更改、撤销）、哪个文件、何时、前后哈希、简短 diff，以及完整的先前文本，以便 **撤销** 能在不依赖其他任何东西的情况下将文件放回。撤销本身也是一次日志变更，因此可以依次撤销。有两类行无法撤销并会说明：其先前文本包含凭据的行（存储的副本已脱敏，恢复它会把脱敏标记写入 Bot 的记忆），以及其先前文本太大无法保留的行。

Bot 的写入在回合边界被捕获。当回合开始时，应用记录每个记忆文件的内容；当回合结束时，任何不同之处都记录为该聊天的 Bot 工作。回合之间更改的文件——比如在 Obsidian 中编辑的——记录为你的，*应用外更改*。同一 Bot 的两个线程同时运行时都会做 diff；变更归入先完成的那个线程。日志记录绝不会让回合失败：无法写入的行会被记录并丢弃。

## 文件内的约定

文件是你和 Bot 的，任何 markdown 都可以。应用本身将它们作为纯文本读取，从不要求结构。Bot 写入时遵循的约定是：

- **`MEMORY.md` 中的带日期条目。** Bot 在任务中添加的笔记是一个带日期和来源聊天的项目符号：
  `- 2026-09-10 · from chat "Follow-up" · the user prefers short replies`。
  用户手写的无日期项目符号同样有效。
- **被取代，而非删除。** 当一条事实被替换时，旧项目符号被划删除线并标注日期而非移除——
  `- ~~the office is in Pune~~ · superseded 2026-09-10`——因此文件本身显示发生了什么变化。划掉的行仍计入预算；文件填满时精简它们。
- **每日日志** 位于 `memory/log/YYYY-MM-DD.md`，是 Bot 所做之事的日记；它们从不加载到对话中，供你在面板或 Obsidian 中阅读。
- **Until 日期。** 在已知日期不再为真的事实以 `· until YYYY-MM-DD` 结尾（`memory_update` 为此接受 `until` 字段），并在
