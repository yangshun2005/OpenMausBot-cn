# 本地化

OpenMausBot 的翻译随应用一起发布，运行时不会请求翻译服务，贡献者也不需要 API 密钥。`src/locales/en.json` 中的英文是源目录；其他 JSON 文件是部分覆盖层，缺失的键会回退到英文。

## 添加或更新语言

1. 使用小写的 BCP-47 文件名，如 `de.json` 或 `pt-br.json`。
2. 每个键必须与英文键完全一致，占位符如 `{name}` 必须原样保留，包括重复出现的占位符。
3. 在 `src/locales/index.ts` 中注册新的语言包。
4. 运行 `pnpm i18n:check`，并在 **设置 → 通用** 中测试该语言。

`pnpm i18n:check` 是确定性的。它会校验 JSON 结构、未知或空条目、语言文件名的字母大小写、占位符一致性，以及每个翻译值附带的英文源哈希。如果英文文案发生变化，旧翻译会校验失败，而不会悄悄看起来是最新的。缺失的翻译是允许的，因为运行时有英文回退。

## 可选的模型辅助草稿

仓库包含一个维护者工具，会把缺失或过期的英文字符串发送给已安装并已认证的 Claude CLI。该 CLI 通常会把字符串发送到其配置的云端模型，可能消耗订阅或 API 配额；“本地”描述的是 CLI，而非推理运行的位置。

```sh
# 安全、无工具的 Claude 模式
node scripts/generate-locale.mjs it "Italian"
```

现有语言包只刷新缺失或英文源已变化的键，其他键的已审校翻译会保留。仅在有意重新起草整个语言包时才使用 `--force`。该工具在安装任一文件之前，会拒绝散文、代码围栏、缺失或凭空捏造的键、空值以及被改动的占位符。

对于人工编写或编辑的语言包，请审校并记录每个现有值对应的英文源：

```sh
node scripts/generate-locale.mjs pt-br --accept
pnpm i18n:check
```

将 `src/locales/source-hashes.json` 与目录一起提交。该哈希不包含任何翻译内容或凭据，只是让 CI 能检测出过期的文案。

模型输出是草稿，不是权威。提交前请审校语气、术语、语法、产品名称以及安全敏感文案。AI 翻译不会在 GitHub Actions 中运行：常规 CI 保持确定性、无密钥，且对 Fork 安全。
