# 预设机器人

预设是 **新建机器人** 中的命名起点。选择预设会填入新机器人的名称、标题、描述、常驻指令和外观，按下 **创建机器人** 时还会带上预设的技能、剧本和起始笔记。创建机器人前，每个字段都可以修改。

预设来自共享文件（团队文件或别人发给你的预设文件），或来自你组织的货架（**模板 → 来自 {Organization}**，见 [org-library.md](org-library.md)）。在新建机器人的 **起始角色** 列表中，组织的预设排在最前，位于 **来自 {Organization}** 下，然后是 **导入的预设**，最后是内置角色。

## 预设包含什么

预设是一份允许清单，只能携带：

- 名称和简短描述；
- 新机器人的名称、标题、描述和常驻指令；
- 外观：颜色、吉祥物和图片；
- 剧本；
- 技能（仅 `SKILL.md` 文本，绝不含脚本）；
- 起始笔记（`MEMORY.md` 和主题笔记）。

预设没有模型、文件夹、计算机、审批级别、已连接应用、MCP 服务器、浏览器、对等体或例程的字段。你在新建机器人（或新建机器人默认值）中为这些选择的任何内容都保持不变，因此预设永远不会扩大机器人的权限。每个存储的预设都通过与其他导入相同的包解析器读取，所以手工编辑过的预设也只能表达文件允许的内容。

## 来源决定技能的开关状态

- **来自文件：** 预设的技能以 **关闭** 状态添加，与共享文件中的所有技能一样。阅读后在机器人的技能设置中开启。
- **来自组织：** 技能以 **开启** 状态添加，因为组织的管理员已发布它们。每个技能还带有安装的技能戳记（契约 §3.2：安装、技能名称、发布版本，以及发布时和写入时的 `SKILL.md` 哈希），标记为 `via: "preset"`，这样后续自动更新就能区分你自己的编辑和发布者的更改。机器人仍属于你，不属于包：它从不保留已添加的包，因此你删除过的团队可以再次添加。

新建机器人对话框会在创建机器人前说明适用哪种情况。预设的技能和起始笔记优先于新建机器人默认值中同名的技能或笔记。机器人会记录其来源（`installedPackage` 带 `presetKey`）。

来自已撤回组织发布版本的预设，或来自你已删除团队的预设，不再提供；已用已撤回预设创建的机器人，其该发布版本的技能会被关闭（仅一次；重新开启由你决定）。提供哪些预设遵循组织库自身的状态（`server/org-library.ts` 中的 `OrgLibrary.installStatuses()`），而非单独读取 `state.json`，因此新建机器人和货架永远不会不一致。没有组织就没有安装，也不会隐藏任何内容。再次添加同一组织包（例如你删除过的团队）会就地刷新其预设，而不是添加副本。组织预设由管理员管理；导入的预设可在起始角色列表下用 **从新建机器人中移除** 删除（无需确认步骤）。

## 共享预设

两种方式，保存的文件格式相同（[team-sharing.md](team-sharing.md)）：

- **随团队共享。** 在 **共享团队…** 中勾选 **将我的新建机器人默认值作为预设包含**。除非你勾选，否则它是关闭的：你的新建机器人默认值在共享前属于你。团队的 **包含起始笔记** 复选框也决定预设的笔记是否包含在内。
- **单独共享。** **设置 → 通用 → 新建机器人默认值 → 作为预设共享…** 保存一个预设文件：预设及其技能，无团队，无机器人。可选择预设名称、描述、版本，以及是否包含图片和起始笔记。

两种方式下，预设都由你保存的新建机器人默认值经上述允许清单生成，每个文本部分都经过与团队文件相同的密钥脱敏。对话框会列出被移除或省略的内容。没有确认步骤：**保存文件** 就是决定。

预设文件像团队文件一样在 **模板 → 导入** 中添加。预览会显示预设机器人以及文件仅提供的技能；**添加预设** 将预设放入新建机器人，不改动其他内容。只有技能、没有机器人或预设的文件在此无可添加，会被拒绝并给出提示。同一文件添加两次，其预设只提供一次。

## 预设的存放位置

数据文件夹中的 `org-library/presets.json`：每个预设一行（来源、所属安装、包名和版本，以及文件携带的预设原样），外加这些预设使用的技能和剧本定义，这样即使文件或组织发布版本已不存在，仍可从预设创建机器人。本安装上次共享为预设文件的内容（其包 ID 和版本）保存在 `published-library.json` 中，以便下次共享时建议下一个版本。

## HTTP

全部为管理员权限。

- `GET /api/bot-presets` → `{presets: [{id, source: "file"|"org", key, name, description?, packageName, release, publisherName?, bot, skills: [{name, description}], skillsEnabled, playbooks, notes}]}`。
- `DELETE /api/bot-presets/:id` 删除导入的预设；组织的预设返回 `409`。
- `POST /api/bots` 带 `preset: "<id>"` 会将预设的剧本、技能和起始笔记添加到新机器人并打上戳记。名称、外观和指令是请求自身的字段，与任何机器人一样。
- `POST /api/teams/export` 带 `includeDefaultsPreset: true`（可选 `presetName`、`presetDescription`、`presetAvatar` 为 data URL）会将新建机器人默认值预设添加到团队文件。用 `kind: "library"` 代替 `team` 时，保存预设文件（`name`、`release`、`notes`、`includeMemory`、`dryRun` 与团队相同）。
- `POST /api/teams/import` 添加预设文件的预设，返回 `{presets: [{id, key, name}], offeredSkills, bots: [], section: ""}`。`POST /api/org-library/add` 返回相同的 `presets` 列表，安装条目在 `org-library/state.json` 中记录于 `presets` 下（`{<key>: {presetId, r}}`，`r` 为契约 §1.6 的发布侧哈希）。

测试方式见 [verification/presets.md](verification/presets.md)。
